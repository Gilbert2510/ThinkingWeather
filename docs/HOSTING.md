# 公网 Serverless 连接与排查

1.1.0 起，调试版和正式版均连接阿里云 FC 公网 HTTPS 地址：

`https://thinkiner-proxy-pjqxglocom.cn-hangzhou.fcapp.run`

手机/模拟器只需正常互联网，不再要求电脑运行天气后端、USB 转发或本地网络权限。原本机后端、连接脚本、开发 HTTP 放行及 App 内示例模式已退出活跃工程。自动化测试保留，不构成 App 的本机服务入口。

## 原始 API 契约

该 URL 是和风 API 的代理，不是旧 Kotlin 网关的 `/v1/weather` 聚合接口。客户端请求 GeoAPI、Weather v1、空气/预警和生活指数的原始路径，在 Android 数据层进行单位转换、响应聚合和可选失败处理。Key 和 API Host 始终留在云端。

例如已有的 `/v7/weather/now?location=101010100` 仍可用于手动验证；正式客户端优先采用 Weather v1。浏览器返回一个 JSON 不代表所有城市搜索、小时/每日、空气、预警及指数订阅均已可用，应按需要逐项检查。未知权限/地区没有的栏目不伪造。

仓库提供更严格的云端替换实现和部署步骤，见 [serverless/README.md](../serverless/README.md)。本地代码改动不会自动更新已部署函数，必须在阿里云发布后验证。

## 失败如何判断

| 现象 | 优先检查 |
| --- | --- |
| App 显示未连接网络 | 手机/模拟器是否有经过验证的互联网连接，是否存在登录门户/VPN/代理问题 |
| HTTP 429 | FC 控制台调用指标、实例并发/请求配额、API 网关/WAF 限流、和风请求频率或预算；先尊重 Retry-After，避免连续重试 |
| HTTP 401/403 或 JSON code=401/403 | 云端 Key/专属 Host 是否匹配、凭据应用/API 限制、相关产品权限；不向 App 添加 Key |
| HTTP 400/404 | 当前云函数是否支持该原始路径与参数、坐标顺序/精度；不要请求旧 `/v1/weather` 聚合路由 |
| 502/504 或超时 | FC 冷启动、函数超时、出站连通性、上游耗时与返回格式；检查状态和耗时，日志不要输出参数或凭据 |
| 仅空气/预警/生活指数缺失 | 对应接口权限、覆盖范围或数据是否为空；核心天气可继续展示 |
| 刷新失败但有数据 | 当前显示本地缓存，留意过时提示；不会切换为演示数字 |

最初提供的代理始终返回 HTTP 200，因此也必须查看和风 JSON 的 `code`。客户端保留这一兼容检查；仓库替换函数会进一步把业务错误映射成正确 HTTP 状态。无法仅凭某一次 429 判断是欠费、FC 并发还是和风额度，需要控制台证据。

## 预警 `400 invalid_query`

1.2.0 修复旧代理的预警参数白名单遗漏：官方支持 `localTime`，早期函数仅接受 `lang`。客户端现在省略此可选参数，因此兼容当前函数；源码代理已补齐规则。空预警 `metadata.zeroResult=true / alerts=[]` 是正常结果。不要通过隐藏所有错误来处理，真实权限/限流/网络问题仍应保留提示。示例与依据见 [WEATHER_MAP.md](WEATHER_MAP.md)。

## 更换服务地址

默认地址已包含在公开构建配置中；它是公开入口，不是密钥。若将来迁移到其他函数或自定义域名，使用 Gradle 属性 `-PWEATHER_BASE_URL=https://新地址`，重新生成并验证 APK/AAB。只支持 HTTPS，不支持本地 HTTP，也不读取旧 `WEATHER_DEBUG_BASE_URL`。

服务恢复后先验证城市搜索、核心天气和缺省城市，再验证可选内容及实际手机 Wi-Fi/移动网络。构建通过、测试夹具通过与真实云端通过是不同证据，以 [VALIDATION.md](VALIDATION.md) 记录为准。

## 发布前的云端边界

函数实例内缓存和限流会在冷启动时重置，跨实例不共享。需在云端入口配置全局请求配额、最大实例数、预算告警与适用的用户授权；CORS、隐藏 URL 或 APK 中的固定 token 都不能证明调用来自合法客户端。保护源代码中的密钥只是必要条件之一。

应补齐运营者联系方式、隐私政策和实际日志保留策略，核对和风的数据、归属和分发条款。当前凭据无需提供给 Android 项目；控制台修改凭据后，保留环境变量名并重新发布/验证函数。
